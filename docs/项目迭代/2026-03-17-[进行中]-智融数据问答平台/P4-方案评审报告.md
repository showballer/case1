## 一、架构变更说明

### 1.1 变更原因

用户要求将技术栈从 **前后端分离架构（Next.js + NestJS）** 改为 **Next.js 全栈架构**。

### 1.2 核心变更

| 变更项 | 变更前 | 变更后 |
|--------|--------|--------|
| 架构模式 | 前后端分离 | 全栈统一 |
| 后端框架 | NestJS | 移除（使用 Next.js API Routes） |
| 认证方案 | JWT + Passport | NextAuth.js |
| 目录结构 | Monorepo 多应用 | 单一 Next.js 项目 |
| API 层 | NestJS RESTful | Next.js API Routes |

### 1.3 变更优势

- ✅ **简化部署**：单一应用，无需管理多个服务
- ✅ **类型共享**：前后端共享 TypeScript 类型
- ✅ **开发效率**：无需维护 API 契约，自动类型推导
- ✅ **SSR 支持**：服务端组件提升首屏性能
